# 记忆系统优化方案对比实验 —— 汇总（2026-09-12）

基准：`scripts/mem/bench/gold.jsonl`（41 主题，来自 01-index.md 关键词路由）+ `gold_paraphrased.jsonl`（每主题 3 条无泄露改写问法，123 题）。

## 实验 1：新会话「该读哪个文件」——启动上下文变体 × LLM 路由（任务 40）

同一个 sonnet Agent 只看一份启动上下文，为 123 条改写问法选 Top3 文件。

| 启动上下文 | 字数 | Hit@1 | Hit@3 | 说明 |
|---|---:|---:|---:|---|
| 现有 01-index.md | 24,658 | 100% | 100% | 基准本身抽自它，天然有利 |
| boot 完整（`mem.py boot`） | 14,435 | 87% | 93% | |
| **boot 紧凑（`--kw 3`, summary 截 60 字）** | **9,880** | **90%** | **95%** | 更短反而更准：噪声少 |
| 仅总览 §8 指引表 | 3,184 | 73% | 78% | 覆盖面不够 |
| 纯算法 `mem.py search` hybrid（无 LLM） | 0 | 59% | 76% | 255 ms/题 |

紧凑启动包 6 处失误只有两个根因：① `knowledge/architecture-spider.md` 的 Front Matter 没写「配置节 / yaml Duration / 线上配置同步」；② 一个主题被索引路由到 `sessions/2026/2026-09-08-res_lc数据纳入后台.md`，而 boot 默认不列历史会话——该会话内容本该提炼进 `knowledge/architecture-nc-js.md` 或 `architecture-api.md`。两者都是元数据/提炼问题，不是加载方案问题，修好后紧凑启动包可逼近 100%。

**结论**：Front Matter 生成的紧凑启动包用 40% 的字数达到 90% 路由准确率；LLM 读目录比算法检索强得多，`search` 定位为补充手段（找章节、找 boot 里没列的 sessions）。

## 实验 2：总览瘦身草案的信息保真（任务 30 + 50）

- 草案 `overview-trimmed.md` 4,000 字（原 27,124 字，-85%）；§2 历史 26 条原文进 changelog、36 条指针化、16 条删除（详细文件已有）、**6 条只存在于总览需先回写详细文件**。
- 保真评测：从原总览出 15 道「开工前必须知道」的题，只拿草案作答、最多再开一个文件读一段：**15 题全部完整回答，0 失败；总额外读取 4,665 字**（原总览 17%），7 题零额外读取。
- 草案必须补回 3 处：① 「配置文件明文 AK/SK 禁止写入记忆」安全红线丢失且无指针；② GitHub OAuth「上线顺序先网关后前端」只能通过日期通配指针间接到达，需直接写回或改精确文件名；③ 队列 v2「无回滚路径」风险只活在总览一句话里，删前先落到 `current/tasks.md` 或 `risks.md`。
- 有争议的取舍（任务 30 提出）：4,000 按字符算是硬卡线，§5/§6 各砍到 7 条；若按中文字数口径可放宽到约 5,500 字符回到 10 条。§2 的 P4 条压成 2 行后把细节推给 `current/tasks.md`，**tasks.md 瘦身必须同轮做**，否则只是把膨胀挪了地方。

## 实验 3：检索算法配置对比（任务 10）

18 组配置，在 123 条改写问法上（Hit@1 / Hit@3 / Hit@5 / MRR）：

| **hybrid jina-v2-base-zh（新默认）** | **0.68** | **0.85** | **0.89** | **0.77** | 建索引 180 s，模型 640MB |

RRF 权重 {1.0,1.3,1.6,2.0}、K {10,30,60}、min_sim、切块 {300,600,1200}、boost 开关扫描均未超过现默认（1.3 / 30 / 0.35 / 600 / 开）。
最差 5 个主题中 3 个是 Front Matter 关键词覆盖不足，1 个是内容只在 sessions/ 里且被降权，1 个是「当前该做什么」这类元问题本就该走固定加载而非检索。未发现算法系统性缺陷。

**已落地**：`mem.py` 默认语义模型改为 jina-v2-base-zh；缓存文件名始终带模型名避免维度混用。

## 综合建议

1. 采用「总览 ≤ 4,000~5,500 字 + 紧凑 boot（≈10k 字）」作为常驻，替代现在 54k 字；新会话固定成本降到约 1/4。
2. 01-index.md 改为 `mem.py boot --kw 3` 的生成物；原「关键词索引」的问句迁到各目标文件 `questions:` 字段（boot 与 search 同时受益）。
3. 瘦身前先做三件事：回写 6 条总览独有事实、修 architecture-spider.md 等文件的 Front Matter、把被路由到 sessions 的内容提炼进 knowledge。
4. `current/tasks.md` 与总览同轮瘦身；`lint` 进会话收尾清单。
