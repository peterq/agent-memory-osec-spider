# 角色 50：四仓库 CI + proto 生成自动化（提案 8）

短名 `ci`。worktree：`common-wt-ci`、`spider-wt-ci`、`api-wt-ci`、`storage-wt-ci`（分支 `feat/ci`）。

## 目标

1. 四个 Go 仓库各加 GitHub Actions（远端都在 GitHub：`1second/enfi-resource-common`、`PPSub/enfi-spider-go`、`PPSub/enfi-resource-api`、`1second/enfi-resource-storage`）：`go build ./...` + `go vet`（只对无存量告警的包，白名单方式）+ 安全单测。
   难点：下游仓库 `go.mod` 用相对 `replace => ../enfi-resource-common`，CI 里要先 checkout COMMON 到同级目录（`actions/checkout` 指定 `path` + `repository`，私有仓库需要 `secrets.COMMON_REPO_TOKEN`，README 写明要配的 secret 名，**不要造值**）。
2. **隔离直连生产的测试**：凡是会连生产 ES/DB/网关或联网打网盘接口的 `_test.go`，加 `//go:build live` 标签（先 `grep` 找：`ConnectProdSpiderGw`、`UseProdSpiderGw`、`_live_test`、`_prod_test`、含真实主机名/`es-cn-`/`192.168.` 的测试、`*_IT=1` 环境变量门控的测试）。CI 默认不带该标签。
   注意：`services/gateway/download_scheduler/pan_download/{alipan_download/alipan_dl_test.go,bnd_download/bnd_dl_test.go}` 由 `secrets` 角色负责，你**只在文件第一行加标签**，不动别处。
3. COMMON proto 生成全自动：`Makefile` 目标过期（路径/文件名对不上、新增 proto 未纳入），`common_message.proto` 的 `go_package` 仍是旧仓库名 `PPIO` 导致 `gen.sh` 后要手工 sed。改成：`make proto` 一条命令生成全部 proto（含 spider 子目录全部 `.proto`）、`go_package` 改对、CI 加「生成物是否与 proto 一致」检查（生成后 `git diff --exit-code`）。需要本机有 `protoc` 与插件，先查版本；没有就把版本要求写进 README 并跳过本地验证，汇报里说明。
4. 各仓库 README 加「本地怎么跑 CI 同款检查」一节（`make ci` 或脚本 `scripts/ci.sh`）。

## 必读

`agent-memory/procedures/workflow-本地构建与验证.md`（存量告警清单、验收口径）；COMMON `Makefile`、`rpc/spider/gen.sh`、`cmd/proto/`；`agent-memory/current/risks.md` R3。

## 文件所有权

四仓库：`.github/workflows/ci.yml`、`scripts/ci.sh`、`README.md`（只加一节）、需要加 build tag 的 `_test.go` **第一行**；COMMON 另加 `Makefile`、`rpc/**/gen.sh`、`common_message.proto` 的 `go_package` 与由此重生成的 `*.pb.go`。**不要加密钥扫描 job**（`secrets` 角色做 `secrets.yml`）。

## 验证

本地跑 `scripts/ci.sh` 四仓库通过；`go test ./...`（不带 live）在每个仓库能跑完不打生产（观察无网络连接到生产主机：测试若报连接失败就说明还有漏网的，继续加标签）。`act` 不要求。

## 交付

分支/提交、workflow 文件说明、被加标签的测试文件清单、vet 白名单、需要用户在 GitHub 配置的 secret 名与权限、本地验证输出。
