# agent-tasks —— 子 Agent 任务简报

## 这个目录解决什么问题

主控 Agent 派子 Agent 干活时，任务描述往往很长（仓库位置、契约路径、必读文件、硬性约束、
验证命令、交付要求）。多个子 Agent 之间这些内容大量重复，如果每次都塞进 prompt：

- 主控的上下文里会积累 N 份几乎相同的文字，Token 浪费随子 Agent 数量线性增长；
- 追加指令、验收、下次会话续做时，这些上下文已经散落在历史消息里，无法复用；
- 同一份约束在多份 prompt 里被复述，容易写出不一致的版本。

约定：**任务描述落盘成文件，prompt 只给路径**。

## 目录结构

```text
agent-tasks/
├── README.md                          # 本文件
└── YYYY-MM-DD-<任务名>/
    ├── 00-shared.md                   # 所有子 Agent 都要读: 背景/仓库/契约/硬性约束/环境禁忌
    ├── 10-<角色>.md                   # 某个子 Agent 专属: 落点/接口/交互要求/验证命令
    ├── 20-<角色>.md
    ├── 90-review.md                   # 验收 Agent 专属: 验收清单与判据
    └── 99-notes.md                    # 可选: 执行过程中主控追加的裁定、变更、返工要求
```

编号约定：`00` 共享，`10/20/30…` 各开发角色，`90` 验收，`99` 过程追加。

## 主控怎么用

派子 Agent 时 prompt 压缩成几行，只给绝对路径：

```text
你是本任务的<角色>。按顺序读这两个文件, 然后完成其中属于你的工作:
1. /home/peterq/dev/projects/1s/enfi-resource-common/agent-tasks/<任务目录>/00-shared.md
2. /home/peterq/dev/projects/1s/enfi-resource-common/agent-tasks/<任务目录>/10-backend.md
完成后按 10-backend.md「交付」一节汇报。
```

需要追加要求或返工时，**改文件 + 通过 SendMessage 告诉子 Agent 重读**，不要在消息里复述整段。

## 写简报的要求

- `00-shared.md` 只放**真正共享**的内容。某项只有一个角色用得上，就写进它自己的文件。
- 硬性约束（会导致返工或生产事故的）要单独成节并标明，例如"绝对不要跑 pnpm build，会真实
  上传生产 OSS"这类环境禁忌。
- 必读文件列清单并说明**为什么**要读，子 Agent 才知道该从中提取什么。
- 验证命令写成可直接复制执行的完整命令，别让子 Agent 猜。
- 任务完成后目录保留，它就是这次协作的可追溯记录；长期有效的经验再提炼进 `agent-memory/`。

## 与 agent-memory 的分工

| | agent-tasks/ | agent-memory/ |
|---|---|---|
| 内容 | 一次具体任务的作业指导书 | 跨任务的长期知识与经验 |
| 生命周期 | 任务期间有效，之后作为记录留存 | 持续维护、提炼、归档 |
| 读者 | 本次任务的子 Agent | 每个新会话的主控 Agent |
