# 子 Agent 任务简报落盘

## 问题

[用户确认 2026-09-08] 派子 Agent 时任务描述往往很长（仓库位置、契约路径、必读文件、硬性约束、
验证命令、交付要求）。多个子 Agent 之间这些内容大量重复，如果每次都写进 prompt：

- 主控上下文里积累 N 份几乎相同的文字，Token 浪费随子 Agent 数量线性增长；
- 追加指令、验收、下次会话续做时，上下文散落在历史消息里无法复用；
- 同一份约束被复述多遍，容易写出互相不一致的版本。

## 做法

**任务描述落盘成文件，prompt 只给绝对路径。** 正本约定与目录模板见 `agent-tasks/README.md`
（COMMON 仓库根下），此处只记要点：

```text
agent-tasks/YYYY-MM-DD-<任务名>/
├── 00-shared.md    # 所有子 Agent 都读: 背景/仓库分支/契约/硬性约束/环境禁忌/交付要求
├── 10-<角色>.md    # 各开发角色专属: 落点/必读文件(并说明要提取什么)/实现要点/验证命令
├── 90-review.md    # 验收专属: 分档判据 + 一票否决项
└── 99-notes.md     # 可选: 过程中主控追加的裁定、变更、返工要求
```

派单时 prompt 压到几行：

```text
你是本任务的<角色>。按顺序读这两个文件, 然后完成其中属于你的工作:
1. <绝对路径>/00-shared.md
2. <绝对路径>/10-backend.md
完成后按 10-backend.md「交付」一节汇报。
```

追加要求或返工：**改文件 + SendMessage 让子 Agent 重读**，不在消息里复述整段。

## 有效的原因

- 共享上下文只写一遍、只占一次主控输出；角色数从 2 涨到 6 时收益线性放大。
- 文件是可追溯的作业指导书：验收 Agent 直接读同一份判据，不依赖主控转述，避免"传话失真"。
- 跨会话可续：下次会话读目录就能接着干，不必从历史消息里考古。

## 注意事项

- `00-shared.md` 只放**真正共享**的内容；只有一个角色用得上的写进它自己的文件，否则共享文件
  会退化成大杂烩，每个子 Agent 都要读一堆无关内容。
- 必读文件要列清单**并说明为什么读**，子 Agent 才知道该从中提取什么。
- 会导致返工或生产事故的禁忌单独成节（例：NC-JS 跑 `pnpm build` 会真实上传生产 OSS）。
- 验证命令写成可直接复制执行的完整命令，别让子 Agent 猜脚本名。
- **子 Agent 有两种高频失败模式，提示词里要提前堵住**：
  ① **卡在等自己起的后台任务**——它自己起了后台命令再去等通知，而通知永远不会来，整轮空耗；
  对策是**提示词里直接禁用 Monitor / 禁止"起后台任务再等"**，要么前台跑完，要么分两次派单。
  ② **把"跑全量"当成验收的必要条件**——为了"证明跑通"去跑全量数据，烧掉大量时间和站点配额；
  对策是提示词里**明确写"抽样对账即可"**并给出样本量。这两条各能省掉整轮往返。
- 任务结束后目录保留作为协作记录；长期有效的经验再提炼进 `agent-memory/`。
- **主控自己产出的东西要当场提交**（契约、生成代码、脚本修复）。留在工作区里，子 Agent 会
  面对来路不明的改动——本次前端因此把已生成好的 TS 契约又重新生成了一遍。
- **不要采信子 Agent 的转述，每一层都独立复核**。本次前端核实时发现它转派出去的那份
  N2 根本没落实；验收方复核时又发现前端漏了一个 `-1` 未知态哨兵、且 mock 把该场景写错
  导致从未被真正测过。每一层都抓到了上一层的漏网之鱼。
- 子 Agent 可能**自行转派再停在"等待回报"**上，把活留在工作区不提交。收尾时按仓库
  `git status` 核实真实状态，而不是按它的汇报；必要时唤醒并明确要求"自己做完，不要再转派"。
- 与 `agent-memory/` 的分工：`agent-tasks/` 是一次任务的作业指导书（任务期有效，之后留存），
  `agent-memory/` 是跨任务的长期知识（持续维护、提炼、归档）。
