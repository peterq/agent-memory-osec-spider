# 决策：停止磁力资源的采集与入库

## 背景

项目早期同时采集网盘分享链接与 BT 磁力链接（`keyword_magnet` 命令、
`resource.SaveMagnetResource` → `storage.UpsertMagnet` → ES 索引 `enfi_magnet_v3`）。
2026-09-02 调研 kkpans 站点时，就"该站 415 条磁力如何入库"提问，用户借此明确了全局范围。

## 最终决策

- [用户确认] **磁力链现已不处理、不入库。项目只处理 4 种网盘类型资源：**
  `bnd`(百度) / `ali-share`(阿里) / `quark`(夸克) / `xunleipan`(迅雷)。
- 新写的任何爬虫**都不应再调用** `resource.SaveMagnetResource`，
  也不应去抓站点的磁力接口。

## 影响范围

- **新增爬虫**：采集范围只考虑上述 4 种网盘类型。kkpans PRD 已据此删掉磁力部分。
- **存量不动**：`resource/magnet.go`、STORAGE 的 magnet worker、ES 索引 `enfi_magnet_v3`、
  API 的 `/api/v2/bt` 查询接口**均保留**，本决策只约束"不再产生新的磁力数据"，不是删功能。
- [事实] `keyword_magnet` 命令仍在 `spider.go` 的命令表里，但**未出现在 `deploy.sh` 的服务列表中**，
  即线上本就没有在跑——决策与现状一致，无需额外下线动作。

## 复盘条件

若业务重新需要 BT 取证证据，需重新评估：届时基础设施仍在，主要成本是重启采集端。

## 当前状态

生效中。
