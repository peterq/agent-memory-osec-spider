# 决策：配置按进程拆代码, 不拆配置文件

## 背景

2026-09-08 用户提出"配置按服务拆分"。当时的会话把它做成了**拆 YAML 文件**：网关一份、
爬虫一份，`deploy.sh` 按子命令选文件，再加一道运行时断言 `MarkCurrentProcessAsGateway`
防网关误连自己（SPIDER `4d7fc5b`/`7c05d00`，从未部署）。

2026-09-09 用户明确纠正（原话要点）：
- 不是拆文件，是拆代码：`config.Get()` → `config.GetGateway()` + `config.GetProxy()` …，
  甚至可以通过 package 隔离；
- 不同进程使用不同配置结构体；
- 禁止导出 `config.Config` 全局变量，初始化从 `init` 移入 `GetXXX()`；
- 这样才能保证注入问题，而不是靠配置文件不写某项来避免触发自动注入；
- 相反，配置文件应尽可能用同一个，减少维护成本。
- 追问后补充：方案 1（package 隔离）+ 构建 tag 保证；**section 结构体本身可以共享，
  只是最终组合不共享**。

## 最终决策

- `config` 根包只放 section 类型 + `Common`（所有进程共有的段）+ 无状态助手；
  **删除** `config.Config`、`config.Get()`、`init()` 加载、`MustSpiderGwConn` 全局版、
  `MarkCurrentProcessAsGateway` 断言。
- `config/internal/loader`：惰性加载，进程内只允许一种角色（第二种 `Get()` panic，运行时兜底）。
- 角色包各自 `Get()`：`config/gateway`（`!crawler_only`）、`config/crawler`、`proxyprov`、
  `lifecyclechecker`、`doccrawler`、`devops`、`downloader`（均 `!gateway_only`）。
  同一 yaml 键路径可在不同角色里是不同宽度的类型（爬虫读完整 `ProxyConfig`，网关只读
  `ProxySubConfig{Redis,PubChannel}`）。
- `spider.go` 拆为公共 / `commands_gateway.go` / `commands_crawler.go` 三份带 tag；
  `scripts/check_config_isolation.sh` 用 `-tags gateway_only` / `-tags crawler_only` 各编一次
  main 作为编译期隔离检查。默认构建仍是全功能单二进制，`deploy.sh` 不变。
- 多角色共用的库包（`db`、`resource`、`services/gateway/valid`…）不得 import 角色包：
  公共段走 `common.Get()`，角色相关值由调用方传入（`OnProxyWith(sub, cb)`、`NewSpiderGwConn(addr, service)`）。
- **配置文件保持一份** `res/spider.prod.yaml`：`deploy.sh` 回退单文件；本地 `_note/config` 两份用
  `scripts/config_v2_merge_by_service.py` 合回（键路径级、不打印值）；拆分脚本删除。

## 决策原因

隔离靠类型：网关的根结构体里根本没有 `spider_gateway`，注入器无从注入、代码引用不了就编译不过。
靠"文件里不写某项"是数据层面的绕行，一改文件就失效；两份文件又把维护成本翻倍。

## 影响

- 全仓 `config.Config` / `config.Get()` / `config.Hostname` 约 80 处调用点迁移到角色包。
- `gw_config.Hostname` 由变量变为函数。
- `proxy_provider.OnProxy(cb)` 只能在 proxyprov 角色进程调用；其它进程用 `OnProxyWith`。
- 上线：纯代码变更，随下次网关重启 + 爬虫容器分批重部生效；配置对象不动，回滚即回滚二进制。

## 复盘条件

出现"某个进程需要另一个角色的节"时，优先给该进程角色的根结构体加一个**窄类型**读同一键路径，
不要让它 import 另一个角色包，更不要把节塞进 `Common`。

## 代码位置

- `./spider config_show <角色>`（查看某角色实际读到什么配置，config_show 子命令）
