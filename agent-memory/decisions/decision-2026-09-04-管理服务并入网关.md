# 决策：管理类服务并入 spider_gateway 进程

## 背景

`queue_admin`（队列监控管理系统）2026-09-04 上线时是**独立子命令/独立进程**，理由是
"网关是常驻关键服务、长期不重启，管理系统要能独立迭代重启"（见
`knowledge/architecture-nc-js.md` §7 第 3 点）。上线当天即暴露成本：
需要 SLB 加 7543 UDP(+TCP) 监听、res1 安全组对 SLB 放行、前端要维护第二条 RTC 连接与
第二套 host/port/token 配置、deploy.sh 要单独一条服务条目并指向网关的 OSS 配置。

## 决策（用户 2026-09-04 拍板）

1. `queue_admin` 并入 `spider_gateway` 进程，代码目录移到 `services/gateway/queue_admin/`。
2. **日后其他管理类需求也放在 `services/gateway/` 之下，不再新增进程。**
3. 对外端口复用网关：RTC **7542**（`gw_config.RtcListenPort`）+ 原生 gRPC **:8082**
   （`config.Services.Gateway.ListenAddr`），鉴权统一用网关 `rtcHandshake` 校验
   `gw_config.RtcToken`。独立的 7543 / 127.0.0.1:7581 / 独立 `rtc_token` 全部删除。

## 代价与已采取的对策

| 代价 | 对策 |
|---|---|
| 管理功能出 bug 要重启网关才能修 | 接受（用户决定）。`Register()` 失败只记日志不 `log.Fatal`，不让旁路功能拖垮网关启动 |
| 网关跑在 **osec-res1 + osec-res2 两台**，采集/告警会变双份 | `services/gateway/queue_admin/worker_leader.go`：`dlock` 抢主锁（前缀 `queueAdmin:worker`，TTL 90s、续期 30s、抢不到 10s 重试），`metrics.go` 的 `pollLoop` 与 `alert.go` 的 `run()` 每轮开始判 `IsLeader()` |
| 两台机推同一个 pushgateway grouping key（`job=queue_admin`，无 instance label），非 leader 会用 0 值覆盖 leader 的计数 | `queue_admin_poll_error_total` 由无 label 的 `Counter` 改成带 `host` label 的 `CounterVec`；GaugeVec 无 series 时不会推上去，天然不冲突 |
| 原生 gRPC 从"只听回环无鉴权"变成网关的 `:8082` | 该端口本就承载 `ResSchedulerRpc` 等同样能改队列的写接口，不是新增暴露面 |
| 告警 `sustain()` 的"持续时长"是进程内存态，leader 切换会重置计时 | 已知限制，接受（切换本身罕见，最坏是延迟一轮告警） |

## 影响

- `deploy.sh` 删掉 `queue_admin` 服务条目与 OSS 配置分支，**只需 `./deploy.sh deploy gateway`**。
- `QueueAdminConfig` 删掉 `rtc_listen_port` / `rtc_token` / `grpc_listen_addr` 三个字段。
- 巡检工具 `tools/queue-admin-check` 默认地址改 `127.0.0.1:8082`。
- 前端由此收敛成一条 RTC 连接，见 `decision-2026-09-04-前端合并为spiderAdmin.md`。
- **原"SLB 加 7543 监听"的人工待办直接作废。**

## 复盘条件

若将来管理功能迭代频繁到"每周都要重启网关"，或网关进程因管理功能出现资源/稳定性问题，
再考虑拆回独立进程（但那时应连带解决前端多连接与端口暴露的成本）。
