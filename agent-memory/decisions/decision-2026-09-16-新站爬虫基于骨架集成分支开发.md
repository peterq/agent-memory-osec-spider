# 新站爬虫基于骨架集成分支开发

## 背景

2026-09-16 站点发现第二轮筛出 5 站（duanjuso.cc / pan.xiaozi.cc / qileso.com / jsnoteclub.com / ddys.io），用户要求并行开发。
此时 `sitecrawler` 骨架（十项提案第 11 项）只在 SPIDER `integration/ten-proposals`（`7e79501`）上，master 仍是各站各自复制的旧胶水代码；十项提案整体**待用户确认合并**。

## 备选

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 基于 master，照旧模式写 | 不依赖未合并分支 | 5 站写完还得再迁一次骨架；重复 6 站已踩过的胶水坑 |
| B. 基于 `integration/ten-proposals`，直接用骨架（**采用**） | 一次到位，EngineConfig 核对表可直接套用 | 合并顺序被绑定：十项提案先合，再合 5 站；若十项提案被否要返工 |

## 决策与做法 [Agent 决策，待用户复核]

- 采用 B。5 个 worktree `../spider-wt-site-<短名>`、分支 `feat/site-<短名>`，`git worktree add … integration/ten-proposals`（`scripts/new_worktree.sh` 写死 master，未用），并复制 gitignore 的 `change_proxy_config.go`。
- 集成分支的 go.mod replace 指向 `../common-wt-ten-proposals` 是**未提交**的本地改动，新分支拿不到 → `go build` 缺 `guard/delbreaker`/`panvalid`/`health_rpc`。每个站点分支各加一条 `temp(site): go.mod replace 指向 common-wt-ten-proposals` 提交解决。
- **合并顺序**：COMMON/SPIDER 先合十项提案（按 `agent-tasks/2026-09-16-ten-proposals/95-merge-plan.md`）→ 各站点分支先 `git revert` 那条 temp 提交 → 再合入 master。
- 子 agent 只允许改自己的新文件 + `config/config.go` + `spider.go`；简报在 `agent-tasks/2026-09-16-five-sites/`。

## 复盘条件

十项提案若被否决或大改，本决策作废，5 站需改回 master 旧模式。
