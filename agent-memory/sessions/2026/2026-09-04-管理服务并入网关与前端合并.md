## 关键发现

- **`deploy.sh` 的 `serviceToHosts` 是并入进程时的第一手信息**：`gateway` 挂在
  osec-res1 **和** osec-res2 两台，而被并入的 `queue_admin` 原来只在 res1 跑一份。
  凡是"把单实例服务并进多实例进程"，都要先查这张表，再决定要不要抢主锁。
- **pushgateway 的覆盖陷阱**：`prom.New(url, job, ...)` 只用 `job` 做 grouping key、
  不带 instance label。多实例推同一个 job 时，**无 label 的 `Counter` 会以 0 值覆盖**
  另一台推上去的真实值；`GaugeVec` 没有 series 时不会推、天然不冲突。
  所以给这类自诊断 counter 加 `host` label 是必须的，不是锦上添花。
- **`dlock` 未调 `SetRetryInterval` 时是非阻塞单次尝试**：底层
  `redislock.LinearBackoff(0)` 的 `NextBackoff()` 返回 0，`Obtain` 直接返回
  `ErrNotObtained`。抢主循环因此不会卡住，`IsLockNotObtained(err)` 判一下就能 sleep 重试。
- **合并前端子应用最容易丢的是"Tabs 的挂载语义"**：AntDV `<Tabs>` 默认"首次访问才挂载、
  之后只隐藏"，换成菜单驱动的条件渲染会变成每次切换重新挂载，分页/自动刷新状态全丢。
  本次用 `LazyKeepAlive` 复刻了原语义。

## 做出的决策

- 管理类服务一律并入网关进程，日后不再新增进程 → `decisions/decision-2026-09-04-管理服务并入网关.md`
- 两个后台子应用合并为 spiderAdmin，左侧栏布局 → `decisions/decision-2026-09-04-前端合并为spiderAdmin.md`

## 遇到的问题

- 主会话复核时发现子 Agent 写的窄屏自动折叠逻辑是"每次 resize 都强制折叠"，
  用户在窄屏上手动展开侧栏后任何尺寸变化都会被重新收起；已改成只在跨过 1280px 阈值时折叠一次。
- 无法对新 UI 做视觉验收：页面必须先连上生产网关（需要 RtcToken）才会渲染出正文，
  headless 截图这条路走不通。只做了代码级复核（布局结构/样式/主题 token）。

## 值得沉淀的经验

- 两个仓库的改动互相依赖（前端 `queueAdminRpc` 要挂同一条 transport，前提是后端已并入网关），
  但**接口契约不变**，所以可以并行派两个子 Agent，只要在提示词里把对方的目标状态写死即可。
- 给子 Agent 的第一条铁律必须是"不要在未关闭 deploy 的情况下跑 `pnpm build`"——
  `mfe()` 默认 `deploy:true` 会真实上传生产 OSS，这次因为提示词写在最前面而没有重演。
