## 关键发现

- 网关有两套队列 RPC（`res_scheduler_rpc` 与 `gateway_v2`），用户说的"v2 队列服务"指前者（v2bnd 用的那套）；
  取舍理由见决策文件。
- `deploy.sh` 的 `deployService` 只部署 `serviceToCmd` 第一个词：`bnd="share share_pwd"` 只部署过 `share`，
  `v2bnd="v2bndLoadShare v2bndLoadShare"` 既写错又只部署一个。线上 `v2bndInputPwd` 是手工起的。已拆成单命令条目。
- 旧 filter 里的 `resource.CheckExpiredFromEs` 早已是 `return false` 的空壳，预检没有迁移它不算行为回退。
- 子 Agent 主动去掉的东西（主会话认可）：ali/xl 的 `:9527` 调试代理端口；ali/xl/quark 业务层 8h 互斥锁
  （去重已收敛到网关预检）；并把旧代码里从未触发的 `SubmitValid` 死分支挂到真正的失效路径上（行为修正）。
- `services/aliyun-drive` 的 `checkRecentUpdate` 用分享 id 而非 `md5(shareLink)` 查 STORAGE，疑似历史 bug，未动。
- 线上 `./deploy.sh ps`（09-04）：`share`/`share_pwd`/`keyword_filter`/`ad_share`/`quark_share`/`xunlei_share`/6 个 `keyword_*` 都在跑；
  `devops_check_and_push_clear_queue` 在 4 台机器上跑（`Queue2` 直连，本次未迁移）。
