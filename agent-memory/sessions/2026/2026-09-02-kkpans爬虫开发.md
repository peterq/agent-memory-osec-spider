|---|---|

## 关键发现

- [事实] `gopkg.in/yaml.v2` **支持把 `720h` / `30m` / `300ms` 直接解析成 `time.Duration`**，
  且**显式 `yaml:"baseUrl"` tag 是精确匹配**（无 tag 时才把字段名转小写），
  所以 PRD 里的 camelCase 配置键可以直接用。
- [事实] 站点行为与 PRD 调研完全一致：`platform=quark` 请求 page=52 返回 page=43（页码钳制），
  `platform=other` 返回 400，SSR 页面 `window.__KKPAN_SSR_DATA__=` 后紧跟 `</script>`（无空格、无分号）。
- [事实] `spider_common.ResLinkCommitter` 是**接口**，测试里可以直接注入假实现，
  不需要连 storage gateway 就能跑完整的采集流程。

## 做出的决策

4 处相对 PRD 的实现偏差（均已写入 PRD §11.2）：

1. `KkpansConfig.Enabled` 用 `*bool`，**缺省（配置无 kkpans 节）视为开启**。
   原因：`deploy.sh` 只为 gateway 上传配置，其他服务用宿主机现有 `config.yaml`；
   若缺省关闭，线上配置没同步时服务会静默空跑。所有配置项都有内置缺省值。
2. redis 键前缀做成 `kkpansCrawler.keyPrefix` 字段（默认 `kkpans:`），
   让集成测试能用独立命名空间，不污染线上去重键。
3. 增量首轮（水位线为空）只取第 1 页建立水位线，全量覆盖交给启动时立即执行的全量遍历，
   避免两个模式同时把全站翻一遍。
4. 去重 TTL 由 `fullSweepInterval + 120h` 推导（720h 配置下正好 35 天），
   满足"TTL 必须大于全量周期"的约束且改配置无需手工同步。

## 遇到的问题

- 集成测试首版依赖固定 redis 键，跑第二遍时上一轮的去重键还没过期，导致
  "第二轮应为 0" 与 "至少提交一条" 两个断言互相打架。
  → 用 `keyPrefix = "kkpans-test:<pid>:"` 做命名空间隔离解决。
