# 会话摘要：站点发现常态化任务

## 完成事项

1. 建立常态化任务 `site-discovery`：流程文档 `site-discovery/README.md`、
   历史总表 `site-discovery/history.md`、每次任务报告目录 `site-discovery/YYMMDD/<主域名>.md`。
   触发词 `task site-discovery` / `启动网站发现任务`。
2. 落地可复用工具集 `site-discovery/tools/`（Python，只依赖 requests）：
   `harvest.py`（薅候选域名）→ `triage.py`（批量初筛）→ `sitescan.py`（单站深扫）→
   `pancheck.py`（链接有效率），外加 `selftest.py`（36 项离线单测 + 7 项联网冒烟）。
3. 首轮执行：初筛 47 个站点，深度调研 23 个（派 7 个 sonnet 子 agent 并行），
   **6 个满足全部 6 条验收标准**：`bbs.dyyjmax.org`、`fuxipan.com`、`www.misoso.cc`
   （实际抓 `www.melost.cn`）、`haisou.cc`、`kuakes.com`、`feikuai.tv`。

## 关键发现

- **夸克新增业务码 `41031`「分享者用户封禁链接查看受限」（HTTP 403）= 失效**。
  已亲自复核原始响应确认。生产两套 checker 的 code 白名单都没有它，
  但兜底的 message 正则恰好覆盖了这句文案，所以暂时不会误判——**依赖文案不变，很脆弱**。
- **发现渠道的性价比排序**：开源聚合项目（PanSou/PanHub 的插件目录，一次几十个域名）
  ≫ WebSearch ≫ 站点友链。`harvest.py` 就是把第一条固化下来的。
- **论坛型站点最常见的淘汰原因不是规模也不是有效率，而是「回复可见/登录可见」**——
  kuakeq 17%、qshare 4%~5%、kuakeba 0.9%。评估论坛站必须先量化「游客可见率」，
  规模再大也没用。
- 多个站点（miaosou.fun、alipansou.com）被 Cloudflare Managed Challenge 挡住，
  本地 curl 与 WebFetch 两条独立出口都过不去；另有 hmxz.org 被国内网络劫持到「江苏反诈网」。
  这类站点当前环境无法评估，记进 history 避免下次重复尝试。

## 一个反思：探测强度可能把小站打崩

`xsayang.fun`（第 265 次请求后源站崩溃 40+ 分钟）和 `tv.yydsys.top`（加压后持续 520）
的故障**都不是验证码/403/Cloudflare 这类技术性反爬，而是纯 TCP 层连接失败**——
更像源站基础设施本身脆弱，被中等强度探测打崩。这有两个后果：

1. 把它们记成"反爬强"是误判，记成"站点脆弱"才对（复议时应大幅降速重试，而不是找过盾方案）。
2. 调研阶段就该更保守：**对无 CDN 的小站，默认并发 ≤2、间隔 ≥1s**，
   宁可样本采得慢，也别把站打挂——打挂了反而拿不到 50~100 条合规样本，任务直接失败。
   本次两个站的"证据不足"就是这么来的，是自己造成的。

## 规则补充（会话后期用户追加）

**[用户确认 2026-09-03] 分享链接爬虫一律走 IP 代理池，任何情况下都不允许仅用本机直连；
确认有反爬的站点更要禁用本机 IP 直接访问。反爬站的可行性门槛改为「单 IP ≥10 条/分钟」，
剩余吞吐交给代理池横向扩。**

落实到三处：

1. 验收标准第 6 条改口径（`site-discovery/README.md` §1、§1.5）。
   「有 Cloudflare」「并发 10 触发验证码」不再构成否决理由。
2. 工具集加 `--require-proxy` / `--proxy` / `--proxy-api` / `--no-proxy`，
   代理来源可复用 SPIDER 的蜻蜓代理配置。**拿不到代理即退出码 3，绝不静默降级直连**——
   各 checker 的 `except Exception` 特意放行 `ProxyUnavailable`，否则守卫会被吞掉
   （写的时候就踩了这个坑，靠单测抓出来的）。
3. SPIDER 存量清理：只有 `kkpan.com.go` 和 `www.pansearch.me.go` 两个链接爬虫还在
   `NeedDirect: true`，已改为 `false` 并无条件订阅代理池，`KkpansConfig.UseProxy` 开关下线。

**[事实] 代理池当前是坏的**：dev 与 prod 配置里蜻蜓代理 API 都返回
`code 20014 代理订单异常，token 不正确`。所以上述代理链路只做了离线单测，
**联网路径未经验证**；反爬站复议也必须等代理源恢复。
