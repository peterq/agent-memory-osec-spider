## 关键发现

- **[事实] 修复 3 生效但不够**：每批 2000 父 id 耗时 **63~103 s**，父 id 吞吐 9.1/s → 19.4/s，
  只快 **2.1 倍**；单月剩余需 **约 7.1 小时**（门槛 ≤30 分钟）。
- **[事实] 一直缺失的量纲**：2026-08 单月 join 型 **649,472 父 → 32,449,681 子文档（平均 50/父）**；
  全量约 **7.4 亿子文档**。`_reindex` 限速缺省 2000 rps → 单月下界 **4.5 h**、全量 **4.3 天**，
  30 分钟目标数学上不可达。详见 `archive/2026/failure-copy_child真正瓶颈是子文档量.md`。
- **[事实] 实测只跑到 913 docs/s**（限速的 46%），其余开销在 15.8 亿文档旧索引上的
  `terms{2000 ids}` 检索 + slice 分配不均（一批里一个 slice 独吞 65% 文档）。
- **[事实] `deploy.sh` 的 `scp -C` + `docker rm -f` 不静默两处加固首次在生产生效**：
  60 MB 二进制约 1.5 分钟传完，两台 `docker rm -f` 一次成功，没有再出现"二进制换了容器没换"。
- **[事实] v2 搜索基线抽样方法要用 10 个不同关键词**：同一关键词打 10 次，后几次命中缓存（7~10 ms）
  会把均值拉低。换 10 个关键词后测得 532 ms，与 §7.2 的 533 ms 一致，可直接对比。
- **[事实] `bootstrap_copy_batch` 只在 `config.go` 里，没进 `params.go`**，
  所以 `lc-check -params` 看不到它；作业侧有 `p.CopyBatch<=0 → 2000` 兜底，resume 老作业也能吃到新缺省。
- **[事实] `notify_admin` 用 python `urllib` 会被 403**（Cloudflare 挡 UA），
  用 `MEMERY/scripts/notify-admin.sh`（curl）正常。

## 值得沉淀的经验

**凡是估算，先算工作量的量纲（文档数/行数），再算调用次数。**
