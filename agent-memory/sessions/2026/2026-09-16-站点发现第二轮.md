# 常态化站点发现第二轮（2026-09-16）

- 候选：`harvest.py` 101 个 + V2EX「100+ 网盘搜索引擎」汇总帖等网搜 56 个，过滤后 98 个初筛（代理 + 直连两条出口），18 个深挖（5 个 sonnet 子 agent）。

  - **满足 5**：`www.duanjuso.cc`（≈150 万条、公开搜索接口）、`pan.xiaozi.cc`（≥3 万、近 7 天 +3206）、`www.qileso.com`（id 枚举、需并发 2）、`jsnoteclub.com`（博客型 7000+）、`ddys.io`（反爬需代理、atob 包链接）。

  - 其余 10 站不满足；80 站仅初筛（多为纯搜索引擎、不通或登录墙）。
- 工具沉淀：`tools/ratetest.py`（第 6 条吞吐实测）、`tools/fetchraw.py`（单页原文排障）、`sitescan.py` sitemap lastmod 新鲜度统计、`panlink.py` 解 `atob()` 载荷；离线单测 56 项通过。

## 关键发现

- duanjuso.cc 子 agent 卡在「sitemap 停更 40 天」与「吞吐测不出」；主控逆向前端 chunk（`searchApi-*.js`/`diskApi-*.js`）找到 `POST /v1/search/disk`（`share_time=week` 命中 ≥10000 条、响应直带明文 `link`），`ratetest.py` 直连 46 条/分钟、零限流，改判满足。
- 本地代理池全程只有 1~7 个存活，造成大量 `code=0`/`RemoteDisconnected`；多个子 agent 差点把它当站点拒绝。直连复核 + 两出口对比是唯一可靠的分辨手段。
- 子 agent 用 Monitor 等后台任务会反复「停下等通知」，主控需 SendMessage 催收尾；简报里应明确「不要等 Monitor，用 until 循环或直接收尾」。
- worktree 会话的 Bash 守卫拒绝含变量/heredoc/多段管道的命令，脚本一律先 Write 进 scratchpad 再用字面路径调用。
