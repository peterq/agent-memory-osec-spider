# 2026-09-13 转存下载链路体检

## 完成事项
- 读 SPIDER `download_scheduler` 代码理清投递/解析/下载三段与 redis/MySQL 存储；`deploy.sh ps` + 容器日志 + redis + MySQL 四层取证。
- 新增 `scripts/dl_chain_health.sh` 一键体检；新增 `knowledge/domain-转存下载链路.md`。

## 关键发现
- 解析 worker 自 09-10 起 100% 失败：阿里 3 个在队账号 refresh token 全失效（`InvalidParameter.RefreshToken`），该错误不触发停用，每分钟循环。
- 百度 0 可用账号，解析队列 3,836 条 2025-02 遗留积压。
- 最近一批 `ali_250918_list` 已于 2025-09 全部下载完成（167.8 万文件 ≈35.5 TB），之后无新任务；下载 worker 空闲。

## 做出的决策
- 无（是否续期账号待用户答复）。

## 遇到的问题
- ssh 一度对三台主机同时超时（约 1 分钟后自愈），排查脚本要带 `ConnectTimeout` 并可重跑。
- PolarDB `information_schema.tables.update_time` 为 NULL，无法判断表最后写入时间。

## 后续行动
- 用户决定是否续期阿里/百度账号；若续期，解析 worker 会自动恢复，无需重启。
- 可选改进：`resolve_mgr.startWorker` 把 `InvalidParameter.RefreshToken` 归入停用分类并告警。

## 值得沉淀的经验
- 已写入 `knowledge/domain-转存下载链路.md` §3 坑与 §5 体检判读。
