## 完成事项
- 调研：curl 摸清 `dop-api/opendoc` 接口、Cookie/Referer 要求、两种数据格式（3.0.0 protobuf 区块 / 2.x JSON op）、分块越界行为；Python 原型对账（`agent-tasks/2026-09-16-qqdoc-sheet/ref/`）。
- 开发（sonnet 子 Agent）：userscripts `feat/qqdoc-cloud`（`1df1030` + 返工 `200c450`）、nc-js `feat/qqdoc`（`cc0bed1`）；验收子 Agent 7 项通过。
- 验证：Node 路径 7 个网上文档；本机 fc-chrome 端到端 6 个文档（含 13 sheet/9,131 链接、12 sheet/15,714 链接、老格式 8 sheet/8,345 链接、已删除文档 permanent 错误）。
- 工具沉淀：`scripts/docspider/e2e-local-fcchrome.sh`、`scripts/docspider/cdp-inject-debug.py`；userscripts `scripts/qqdoc-verify.ts`。

## 关键发现
- 老文档返回 JSON op 格式（dver 2.x），随机 7 个文档中 1 个；实现必须双格式。
- protobuf 格式的数字单元格是类型 2，指向共享表第三种条目；doc4 有 129 个索引越界（判断为脏数据，按空处理）。
- fc-chrome 路径"无任何回传"是 e2e 脚本复用旧托管进程所致 → `lessons/failure-端到端复用旧托管进程导致注入旧脚本.md`。

## 决策
- 方案：同一份云端脚本按 host 分派，网关/doc-crawler/契约不改（写入 `knowledge/domain-腾讯文档表格解析.md` §6）。

## 后续行动
- 等用户确认后：合并两分支 → `pnpm build:cloud && pnpm upload:cloud` → 前端发版 → 后台提交腾讯文档任务观察线上 FC 首批结果。
